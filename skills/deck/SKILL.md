# 資料を作る（ModsPDF）

道具は `mcp__mods-pdf__make`・`revise`・`pdf_examples`。見えない時は ToolSearch で `select:mcp__mods-pdf__make,mcp__mods-pdf__revise,mcp__mods-pdf__pdf_examples` を読み込む。それでも無ければ「ModsPDF の Mod が読み込まれていない」と 1 行で伝えて終わる。

枚の JSON の書き方と図の data の形は、このフォルダーの `reference.md`。Haiku に渡す前に必ず読む。

題材: $ARGUMENTS（空なら会話から決める）

Mod は Claude を動かせない。この手順を動かすのは Claude 自身。Mod がするのは、組む・検査する・検査の件数を返す事。

## 1. 骨を決める（強いモデルが自分で。担当には任せない）

聞き返さず、次を決める。足りない数字は聞く前に会話・ファイルから探す。

- 用途と読み手（社内の報告か・投資家向けか・提案か）。紙は横 A4（既定）。画面で見るだけなら `paper: 'wide'`。テーマは色の vivid が既定。黒白は本人が望んだ時だけ `mono`。
- 事業計画なら `template: 'bizplan'` と `plan`（会社・課題・解決策・市場・収支が必須。5 枚の一式になる）。それ以外は枚を自分で並べる。
- 枚の並び: 表紙 → 要点（結論を先に）→ 本文 → 結び。**1 枚に言いたい事は 1 つ**。題名はその主張を 1 文で書く（「売上」でなく「売上は 3 年で 4 倍になる」）。本文は grid で 3〜6 個の panel を詰める。
- 枚ごとに 1 行の指示を作る: `{ 番号, layout, 主張の 1 文, 載せる数字（datasets のキー）, 図の形, 出典 }`。
- **数字はここで確定し、datasets にまとめる**（`{ id: { data, source, asOf } }`）。Haiku に数字を作らせない。出典のわからない数字は載せない。架空・仮の数字は kicker か author に「架空」と書く。
- 図の形は `reference.md` の表から選ぶ。ECharts の見本が要る時は `pdf_examples`（`query` に英語の語。例 `stack bar`）で目録を引き、`id` を渡して option の手本を読む。
- 銘柄・会社の印は `logo: 'NYSE:IBM'` の形で書く（表のセルと KPI）。

## 2. 枚ごとの下書きを Haiku に並列で書かせる

Agent ツールを **model: "haiku"** で、**1 回のメッセージに枚の数だけまとめて**呼ぶ（順番に待たない）。1 担当 1〜2 枚。15 枚を超えるなら担当を増やして 1 枚ずつにする。

担当に渡す文（枚ごとに埋める）:

```
あなたは資料の 1 枚の JSON の下書きを書く担当です。道具は使わず、答えは JSON だけ（```json の囲み 1 つ）を返してください。
【この枚】{ 番号・layout・主張の 1 文・載せる内容 }
【使える数字】{ datasets のキーと形。数字の値は変えない。新しい数字を作らない }
【書き方】{ reference.md の「枚」「panel」「図の形」から、この枚に要る所を貼る }
【決まり】
- title は主張の 1 文（40 字まで）。lead は 2 文まで。
- 数字は datasets のキーで呼ぶ（look の dataset）。文に数字を書く時は datasets の値と同じにする。
- 「推奨」「おすすめ」「買い」「売り」など、投資の勧めに読める語を使わない。事実と数字と条件だけを書く。
- 箇条書きは 1 点 40 字まで。1 枚の panel は 6 個まで。
- JSON 以外の字（説明・謝罪）を返さない。
```

返ってきた JSON を `JSON.parse` できるか・`layout` があるか・panel の項目名が合っているかを確かめる。壊れた枚だけ、同じ担当へ「JSON が壊れていた。直して JSON だけ返して」と 1 回やり直させる。それでも壊れていれば自分で直す。

## 3. 組む

`make` に `{ title, kind: 'deck', slides: [...], datasets, theme?, paper?, author?, lang? }` を渡す。1 回目は `attach` を渡さない（元の原稿と数字が PDF に添付される）。

## 4. 返りを見て、0 になるまで直す

答えの「検査: 字の重なり a・箱の外 b・「…」の切れ c・空いた枚 d」と警告を読む。

- **全部 0 で警告も無い** → 5 へ。
- **0 でない** → 件数の下に「n 頁: …」の文が最大 10 件ある。その枚だけ直す。定石:

| 出た物 | 直し方 |
|---|---|
| 空いた枚（埋まり 85% 未満） | panel を 1〜2 個足す（要点の KPI・短い箇条書き・別の図）。`arrange` を `rows:` で組み直して、薄い行を低く・図の行を高く。1 つの panel の `span` を上げる |
| 「…」の切れ・字が箱の外 | 題・label・name を短くする。列を減らす。panel の個数を減らす。表は 6 列 8 行まで。図の項目を 8 つ以内に（並べるだけの形は Mod が後ろを自動で落とし、「上位 n / N」と注を付ける。落とさせたくなければ先に自分で絞る） |
| 字の重なり | 系列・項目を減らす。図の `height` を上げる。重なりやすい形（sankey・chord・force-graph）は項目を 8 つ以内に |
| 「n 枚目に入らない」 | その block を別の枚に回す。字は自動で 9.5 → 9 → 8.5pt まで下がるが、それでも入らない分は落とされる |
| 図の data の警告 | `reference.md` の data の形に直す |

直す前に、**検査に掛かった枚の絵を強いモデルが見る**。答えの書き先の PDF を Read ツールで `pages` を指定して開く（例 `pages: "3"`）。数字に出ない崩れ（図が読めない・色が区別できない・寄りすぎ）もここで拾う。

直し案が複数ありうる時（図の形を変えるか・panel を足すか）は、問題の枚ごとに Haiku を並列で呼び、「この枚を直した JSON を 2 案、別の方針で」と書かせる。2 案を `revise` でそれぞれ組んで絵を見比べ、強いモデルが良い方を選ぶ（良し悪しは絵で決める。数字のために見た目を悪くしない）。

直しは `revise` を使う。**全体を `make` し直さない**。

```
revise { ops: [{ action: 'replace', index: 3, slide: { … } }, { action: 'insert', index: 5, slide: { … } }], title? , theme? }
```

`index` は 1 から。今の並びは make・revise の答えの「枚の題」。ops は 1 つでも失敗すると何も書かないので、枚の入れ替えがある時は番号の数え間違いに注意する。直したら答えの検査をもう一度読む。**3 回直して 0 にならない物は、その枚の中身を減らして（panel を減らす・図を表にする）切り上げる**。

## 5. 仕上げ

次が全部そろうまで終わらない。

- 検査の 4 つの件数が 0、警告が 0（残る警告は理由を一言添えて本人に渡す）。
- 全枚の絵を 1 度は見た（崩れ・色・数字の食い違い）。
- 題と図の数字が datasets と一致している。出典が足に出ている。
- 推奨に読める語が無い。

本人には、書き先の PDF のパス（絶対パスの生の文字列）、枚数、直した回数と残した警告を数行で返す。PDF には元の原稿 `source.json`・datasets の CSV・話す人の覚えが添付されているので、後から直す時はそこから取り出せると添える。

## 決まり

- 数字は datasets に入れる。枚の文に数字を書き散らさない。
- 色のテーマが既定。黒白（mono）は望まれた時だけ。
- 7pt 未満の字は作らない（Mod が止める）。
- ロゴは `logo` の字だけ。画像を貼らない。
- 直しは `revise`。全体を送り直さない。
- 担当（Haiku）には道具を使わせず、JSON だけを返させる。数字・題・順序の決定は強いモデルが持つ。
